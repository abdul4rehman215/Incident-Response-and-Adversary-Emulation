# 📘 Interview Q&A – Lab 4: Network Forensics with Zeek

---

## Q1. What is Zeek and what is its primary purpose?

**Answer:**  
Zeek (formerly Bro) is a network security monitoring (NSM) platform used to analyze network traffic in real time and generate detailed logs for forensic investigation and threat detection.

---

## Q2. How does Zeek differ from traditional IDS tools like Snort?

**Answer:**  
Snort is primarily signature-based and alert-focused.  
Zeek is behavior-based and log-focused, providing rich metadata for deep network visibility and forensic analysis rather than just alerting.

---

## Q3. How do you capture live traffic using Zeek?

**Answer:**
```bash
sudo zeek -i <interface> <script>
````

Example:

```bash
sudo zeek -i ens5 local.zeek
```

---

## Q4. What are the primary log files generated by Zeek?

**Answer:**

* `conn.log` → Connection metadata
* `dns.log` → DNS queries
* `http.log` → HTTP requests
* `ssl.log` → TLS/SSL activity
* `notice.log` → Alerts (if configured)

---

## Q5. How was JSON logging enabled in this lab?

**Answer:**
By adding the following line to the Zeek configuration file:

```zeek
redef LogAscii::use_json = T;
```

---

## Q6. How was malicious DNS detection implemented?

**Answer:**
A custom Zeek script checked DNS queries against a predefined set of suspicious domains and logged alerts when matches occurred.

---

## Q7. How can Zeek detect port scanning activity?

**Answer:**
By tracking the number of unique destination ports contacted by a single source IP within a defined time window.
If the threshold is exceeded, a port scan alert is triggered.

---

## Q8. How were suspicious user agents detected?

**Answer:**
The script inspected HTTP headers and matched user-agent strings against known scanning tools like:

* sqlmap
* nikto
* nmap
* masscan
* python-requests

---

## Q9. Why is timeline reconstruction important in network forensics?

**Answer:**
Timeline reconstruction allows investigators to correlate:

* Alerts
* Connections
* DNS activity
* HTTP requests

This helps reconstruct attack sequences and understand incident progression.

---

## Q10. How can Zeek logs be analyzed programmatically?

**Answer:**
Zeek logs in JSON format can be parsed using:

* Python (json module)
* jq
* SIEM platforms
* Log aggregation tools

Example:

```bash
jq . conn.log
```

---

## Q11. Why is Zeek important in incident response?

**Answer:**
Zeek provides deep network visibility including:

* Session metadata
* DNS activity
* HTTP behavior
* TLS fingerprinting
* Detection scripting

It enables proactive threat detection and forensic-grade evidence collection.

---

## Q12. What indicators of compromise were identified in this lab?

**Answer:**

* Suspicious user agents (sqlmap, nikto)
* DNS query to malware-example.com
* Simulated port scanning activity

---

## Q13. What makes Zeek valuable for threat hunting?

**Answer:**
Zeek provides structured, high-fidelity logs that allow analysts to:

* Search historical traffic
* Detect anomalies
* Create custom detection logic
* Correlate multi-protocol behavior
